# カメラの較正(キャリブレーション): カメラの位置を測って求める

`src/hand_sim/calibration.py` と `visual_servo.py` の `collect_calibration_samples` の考え方。答え合わせは `scripts/check_calibration.py`。

## 何の問題を解くか

`pixel_to_world` は、画素を世界座標に直すとき、**カメラの位置と視野角が分かっている**ことを前提にしている。


|     | 前提が成り立つか                                          |
| --- | ------------------------------------------------- |
| sim | 成り立つ。XML に `pos="0.2 0 0.6"` と書いてあり、プログラムがその値を読める |
| 実機  | 成り立たない。カメラを置いたあとの位置は、巻き尺などで測るしかなく、測り間違えるのが普通      |


測り間違えると、そのずれがそのまま手先のずれになる(2 cm 間違えると約 24 mm。`scripts/compare_loops.py` の結果)。

## closed-loop との違い

どちらも「カメラの位置のずれ」への対策だが、直すタイミングと対象が違う。


|         | closed-loop(`docs/closed_loop_flow.md`) | 較正(このドキュメント)        |
| ------- | --------------------------------------- | ------------------- |
| 直すタイミング | 動かすたびに                                  | 最初に1回だけ             |
| 直す対象    | 手先と立方体のずれ                               | カメラの位置・視野角そのもの      |
| 毎回必要なもの | 手先の目印の撮影                                | 無し(1回求めれば、以後は使い回せる) |


2つは組み合わせられる。較正でカメラの値を正しくしておき、それでも残るずれ(サーボの誤差など)を closed-loop で直す。

## 何を変えたか(コードの変更)


| ファイル                               | 変更                                                                   | 意味                                       |
| ---------------------------------- | -------------------------------------------------------------------- | ---------------------------------------- |
| `src/hand_sim/calibration.py`(新規)  | `project`、`calibrate_camera`                                         | カメラの位置・視野角を求める本体                         |
| `src/hand_sim/visual_servo.py`     | `collect_calibration_samples` を追加。`locate_cube` などに `fovy_deg` 引数を追加 | 較正用のデータ集めと、求めた視野角を `pixel_to_world` に渡す口 |
| `scripts/check_calibration.py`(新規) | 答え合わせ                                                                | 求めた値が正しいか、立方体への精度が上がるかを確認                |


意図: 「カメラの位置を測る」という人手の作業を、「腕を動かして撮影する」という自動の作業に置き換える。

## 前提: カメラは上空に固定したまま(eye-to-hand)

手先に付けるのは**カメラではなく、青い目印**。カメラは、床の上 0.6 m に固定したまま動かない。
手首にカメラを付ける方式(eye-in-hand)は、まだ試していない(`next_steps.md` の「未決定」)。

## 考え方

「**位置が分かっている目印**」を、カメラで見ればよい。

```
(1) 腕を色々な位置に動かす
(2) そのたびに、手先の青い目印を撮影 → 画素位置 (u, v) を測る
(3) 同じ目印の世界座標は、関節角から計算できる(順運動学。カメラを使わないので、カメラの位置に依存しない)
(4) 「カメラの位置・視野角をこうだと仮定すると、この世界座標の点は、画素のどこに写るか」を計算する(project)
(5) (4) の予想と (2) の実測の画素が、全点でなるべく合うように、カメラの位置・視野角を探す(最小二乗法)
```

- (4) は、`pixel_to_world` の**逆向き**の計算。画素 → 世界座標が `pixel_to_world`、世界座標 → 画素が `project`。
- (5) の探索には `scipy.optimize.least_squares` を使う。ずれ(再投影誤差)の二乗和を最小にする未知数(カメラ x, y, z と視野角の4つ)を、反復で探す。
- 目印の世界座標が「関節角から」出るのが肝。カメラのずれが混ざらない正解値になる。
手先に青い目印を付けたのは、この「カメラと独立に、位置が分かる点」を作るため。
- 求める未知数は4つ(カメラの x, y, z と視野角)。カメラの向きは「真下」と分かっている前提。



## なぜ手先の高さを変えるのか

画素と実寸の倍率は「焦点距離 ÷ カメラから物体までの距離」で決まる。
カメラの高さと視野角は、どちらも倍率を変えるので、**同じ高さの点だけ**では、2つを区別できない。
高さを 3 段階(8 / 15 / 22 cm)に変えると、倍率の変わり方が違ってくるので、両方を分けて求められる。

## 結果(`check_calibration.py`)

腕を 27 か所に動かし、23 点で較正した(4 点は IK が届かないか、目印が見えなかった)。
出発点は、わざと間違えた値 2 通り。どちらからでも、同じ答えに収束した。


|        | 位置 (x, y, z) [m]          | 視野角 [度] |
| ------ | ------------------------- | ------- |
| 本当のカメラ | (0.200, 0.000, 0.600)     | 45.00   |
| 較正の結果  | (0.2003, -0.0005, 0.6051) | 44.45   |


再投影誤差は 0.47 画素。立方体の上に手先を持っていく open-loop のずれは、次のとおり。


| 立方体の位置        | 較正前          | 較正後    | (参考)本当のカメラ値 |
| ------------- | ------------ | ------ | ----------- |
| (0.22, -0.12) | 42.5〜54.9 mm | 1.3 mm | 1.4 mm      |
| (0.25, 0.12)  | 29.1〜37.7 mm | 1.3 mm | 0.9 mm      |
| (0.30, -0.05) | 44.3〜55.9 mm | 1.1 mm | 1.1 mm      |
| (0.15, 0.10)  | 11.2〜21.1 mm | 0.7 mm | 0.4 mm      |


(較正前は、出発点の2通りの範囲。)
較正後は、本当のカメラ値を使った場合とほとんど変わらない精度になった。

高さが 0.6051 m(本当は 0.6 m)、視野角が 44.45 度(本当は 45 度)と、少しずれているのは、**高さと視野角が互いに打ち消し合う**ため。
(高さを少し上げて視野角を少し狭めると、画像の倍率がほぼ同じになる。)
その組み合わせは、使う高さの範囲(今回は 3〜22 cm)では、実質的に同じ位置を指す。だから、ずれた値でも、実用上の誤差は小さい。

## 結果が意味すること

カメラ位置を、わざと最大 5 cm 前後ずらした出発点から較正した。

- 立方体の上に届く精度は、較正前の 11〜56 mm から、較正後は 0.7〜1.3 mm になった。
- これは、本当のカメラ値を使った場合(0.4〜1.4 mm)とほぼ同じ。

つまり、**カメラの位置を測り間違えても、較正すれば、sim で本当の値を知っているのと同じ精度に戻せる**ことを確認した。

## 限界(まだ解決していない点)

- **カメラの向きは「真下を向いている」と分かっている前提。** 実機では、カメラの向きも、少し傾いている。
向きまで求める場合は、より一般的な手法を使う: OpenCV の `solvePnP`(目印の3次元位置と画素から、カメラの位置と向きを求める)や、
`calibrateHandEye`(ロボットの姿勢とカメラ画像から、カメラとロボットの位置関係を求める)。
- **レンズのゆがみ(歪み)は無い前提。** sim のカメラは理想的なピンホール。実機のレンズは、周辺が歪むので、
先にカメラ自体の内部パラメータと歪みを、チェッカーボードを使って求める必要がある(OpenCV の `calibrateCamera`)。
- **目印は sim の青い球。** 実機では、色シールや ArUco / AprilTag を貼る(`docs/closed_loop_flow.md` の「実機に持ち込めるか」を参照)。
貼った位置は CAD や実測で求めて、世界座標の計算に入れる。
- **目印の位置の測定にも誤差がある。** 画素の整数単位の粗さと、グリッパの陰で目印が一部隠れる影響で、再投影誤差は 0.47 画素残った。
- **腕を physics で動かさず、**`qpos` **を直接書いている。** 較正に必要なのは「姿勢が分かる」ことだけなので。実機では、サーボを動かして、エンコーダで姿勢を読む。
