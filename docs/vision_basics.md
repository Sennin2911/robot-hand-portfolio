# 視覚サーボの"目": 2つの手法の概要

`src/hand_sim/vision.py` に書く2つの関数の考え方をまとめる。答え合わせは `scripts/check_vision.py`。

```
カメラ画像 --①色で物体の画素を選び、重心を求める--> 画像上の位置 (u, v) [画素]
           --②ピンホールカメラの式で実寸に直す-->    世界座標の位置 (x, y) [m]
```

---

## 前提: 画像は「数値の配列」

`renderer.render()` が返す画像は、numpy の配列。

| 項目 | 内容 |
|---|---|
| 形 (`img.shape`) | `(高さ, 幅, 3)`。今回は `(480, 640, 3)` |
| 3 の意味 | 最後の軸が色の3成分: `[:, :, 0]`=R(赤)、`[:, :, 1]`=G(緑)、`[:, :, 2]`=B(青) |
| 型 (`img.dtype`) | `uint8`(0〜255 の整数) |
| 画素の指定 | `img[v, u]`。**縦(行)が先、横(列)が後**。 |

座標の呼び方は2つあり、混同しやすい。

| | 横方向 | 縦方向 |
|---|---|---|
| 画像の座標 | **u**(左端が0、右へ増える) | **v**(上端が0、**下へ**増える) |
| 配列の添字 | 2番目 `img[v, u]` の `u` | 1番目 `img[v, u]` の `v` |

> 落とし穴 (`uint8`): 255 を超える計算は**あふれて 0 に戻る**。`img * 2` で 200 → 144 になる。
> 比較や `0.4 * r` のように小数を掛ける分には、float になるので問題ないが、
> 整数のまま足し算・掛け算をするときは `.astype(float)` で型を変えてから計算する。

## ① 色で物体の画素を選び、重心を求める (`find_red_centroid`)

### 考え方

1. **マスク**を作る: 画素ごとに「赤いか?」を判定し、True/False の配列にする。
2. True の画素の位置(u, v)を取り出す。
3. その**平均**が重心(物体の中心の目安)。

### 「赤い」の判定

赤 = R が大きく、G と B が R に比べて十分小さい。例: `R > 100` かつ `G < 0.4*R` かつ `B < 0.4*R`。
アームの黄色は R も G も大きいので、`G < 0.4*R` で除外される。

### numpy の道具

| 書き方 | 意味 |
|---|---|
| `r > 100` | 配列の**全要素**を同時に比較して、True/False の配列を返す(ループ不要) |
| `(A) & (B)` | 要素ごとの「かつ」。**各条件を `()` で囲む**(`and` は配列には使えない) |
| `mask.any()` | 1つでも True があるか |
| `mask.sum()` | True の個数 |
| `np.nonzero(mask)` | True の位置を `(行の配列, 列の配列)` の順で返す = `(v の配列, u の配列)` |
| `配列.mean()` | 平均 |

### 小さな例 (4行×5列の画像)

赤い画素が `(v,u) = (1,2)`, `(1,3)`, `(2,3)` の3つ、黄色が1つある画像で:

```python
mask = (r > 100) & (g < 0.4 * r) & (b < 0.4 * r)
```

```
mask (1=赤い):          vs, us = np.nonzero(mask)
 u→ 0 1 2 3 4              vs = [1 1 2]   ← 行(縦)の位置
v0   0 0 0 0 0             us = [2 3 3]   ← 列(横)の位置
v1   0 0 1 1 0             us.mean() = 2.67,  vs.mean() = 1.33
v2   0 0 0 1 0             → 重心 (u, v) = (2.67, 1.33)
v3   0 0 0 0 0
```

黄色の画素 `(3, 0)` はマスクに入っていない(G が大きいため)。

### 注意点

- 戻り値は `(u, v)` の順。`np.nonzero` の戻りは `(v, u)` の順なので**逆になる**。
- 赤い画素が1つも無いと、空の配列の平均は `nan`(エラーにはならず、警告だけ出る)。
  先に `mask.any()` で確認し、無ければ `None` を返す。
- 条件の数値(100 や 0.4)に決まりはない。実機では照明で変わるので、調整が必要になる。

## ② 画素の位置を実寸に直す (`pixel_to_world`)

### 考え方: ピンホールカメラ

カメラは「小さな穴から入った光が、奥の板(画像)に映る」モデルで表せる。
物体が**カメラから遠いほど、同じ実寸でも画像上では小さく**写る。
今回は真下を向いたカメラで、物体の面の高さが分かっているので、
**画素1つが何 m に当たるか**を決められる。

```
        カメラ(高さ cam_z)
          │ ＼
 焦点距離 f │   ＼        f [画素] : depth [m] = 画像上のずれ [画素] : 実際のずれ [m]
          │     ＼
   画像 ──┴────────      (相似な三角形)
          │         ＼
 depth    │           ＼
          │             ＼
   物体の面(高さ z_obj) ─────●─
```

相似な三角形から:

```
実際のずれ [m] = (画像上のずれ [画素]) ÷ f × depth
```

### 3つの量

| 量 | 式 | 意味 |
|---|---|---|
| 焦点距離 `f` [画素] | `(height/2) / tan(fovy/2)` | 画像の縦の半分が、視野角の半分に当たる、という関係から決まる。`fovy` は**度**で渡されるので、`np.radians` で**ラジアンに直す**。 |
| 奥行き `depth` [m] | `cam_pos[2] - z_obj` | カメラから、見ている面までの距離。**物体の上面**の高さ(立方体なら 0.03 m)を使う。 |
| 画像上のずれ [画素] | `u - width/2`、`v - height/2` | 画像の中心(カメラの真下に当たる点)からのずれ。 |

### 手順

1. `f` を求める。
2. `depth` を求める。
3. 中心からのずれ `(u - width/2, v - height/2)` を、`÷ f × depth` で実寸にする。
4. カメラの真下の位置 `(cam_pos[0], cam_pos[1])` に足して、世界座標にする。

### 符号に注意

`scene_vs.xml` のカメラは「画像の右 = 世界の +x、画像の上 = 世界の +y」。

- **u は右へ増える**: 世界の x も増える → そのまま**足す**。
- **v は下へ増える**: 世界の y は上へ増える → **逆向き**なので**引く**。

### 数値の例 (このシーンのカメラ)

`fovy=45°`、画像 640×480、カメラの高さ 0.6 m、立方体の上面 0.03 m の場合:

- `f = 240 / tan(22.5°) ≈ 579.4` 画素
- `depth = 0.6 - 0.03 = 0.57` m
- 画像の中心から**右に100画素**ずれた点は、`100 / 579.4 × 0.57 ≈ 0.0984` m = 約 9.8 cm だけ +x 側。

### 精度について

赤い画素の重心には、立方体の側面(斜めに見える面)も少し混ざる。そのため、
上面の高さを使っても少しずれるが、この条件では誤差は数 mm 以下(`check_vision.py` の許容は 5 mm)。
これが実機でどれだけ変わるかは、第4週のギャップ計測の材料になる。
