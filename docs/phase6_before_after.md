# 工程 6: 改善の前後の比較(2026-10-30 時点)

新しい指(クッション付き)での、実機の「1 個ずつ掴んで置き場へ運ぶ」試験の結果。データは `outputs/real_trials.csv`(改善前)と `outputs/real_trials_phase6.csv`(改善後)。どちらも、無効(装置の都合・範囲外・腕が動かなかった試験)を除いて数えた。

## 1. 結果

| | 改善前(試験 75〜111) | 改善後(phase6 の 1〜47) |
|---|---|---|
| 有効な試験 | 28 | 44 |
| 成功 | 22(**79%**。95% 区間 60〜90%) | 40(**91%**。79〜96%) |
| 失敗の内訳 | 検出失敗 5、把持失敗 1 | 把持失敗 1、運搬中の落下 1、他を動かした 1、置き損じ 1 |
| **検出失敗を除いた、動作の成功率** | 22/23 = 96%(79〜99%) | 40/44 = 91%(79〜96%) |
| 肩から 10 cm 未満(不安定な範囲)の試験 | 4 件 | 1 件 |
| 平均サイクル時間(成功) | 19 秒 | 19 秒 |

95% 区間は Wilson 法。色の内訳(改善後): 赤 15、緑 14、青 15。

## 2. 読み方(正直なところ)
1. **成功率は上がったが、上がった理由は「検出失敗が 5 件 → 0 件になった」ことだけ。** 動作だけを見ると、96% → 91% で、区間が大きく重なる。差があるとは言えない。
2. **検出失敗が 0 になった理由は、この試験では特定できていない。** 原因として、ほかの要因が混ざっている。
   - 改善後は、深夜の照明で行った(改善前は夕方で、日光が変わる)。**時間帯と照明が違う。**
   - 改善後は、常に `DETECT_EXPOSURE=600 DETECT_GAIN=0` で撮った。
   - 検出の直し(探す範囲の拡大、5 枚の中央値)も入れたが、検出失敗の原因(マーカー不足か色が見つからないか)の記録は、改善後に 1 件も出ていないので、効果は確かめられない。
3. **改善後の試験は、場所の偏りがある。** 34〜47 は、ほぼ同じ場所 (105〜109, −154〜−164) mm を 0° と 45° の置き方で繰り返した(向きの検出の直しの確認のため)。全体の位置の多様さは、改善前より小さい。
4. **範囲の扱い**: 範囲外(マーカー上、肩に近すぎる、遠すぎる)と、腕が動かずに止まった試験は、除いた。改善前の範囲外の除外は後から行い、改善後は試験の途中で止める仕組みを入れたので、**除外の基準が完全には同じでない**。

## 3. 今回の工程 6 で入れた改善
- 検出失敗の原因の記録(`outputs/detect_failures/`)、試験ごとの検出画像の保存(`outputs/trial_archive/`)。
- 探す範囲の枠を左手前まで広げた(立方体が枠にまたがり、向きが誤って出ていた。試験 1、32、33 の原因の有力候補)。
- 向きの検出を、5 枚の中央値で行い、コマごとの揺れが大きいとき警告(`yaw_spread_deg`)。
- 動かす前に分かる範囲外(IK 不可、遠すぎる、可動域の端、机に近い経路、肩に近すぎる)は、動かさず、記録もしない。
- 引数のミスなど、腕が動かずに終わった試験は、記録しない。

## 4. 既知の問題(未解決)
- **緑の向きの検出**: (107, −156) mm で、0° の置き方 → 55°、45° の置き方 → 75° と出る。暗い緑の塊で、向きごとの IoU の山がなだらか(0.77〜0.87)。立方体は挟めるので、成功率には出ていないが、手の向きが面から 10〜20° ずれ、掴む位置がずれる。直す案(立方体の縁の線も使う)は未実装。
- 赤は、置き場の中心から x 方向に、一貫して +9 mm ずれて置く(許容 15 mm の内側)。赤の置き場の座標のずれの可能性。
- 肩から 8〜10 cm は不安定(9 件中 4 件成功)。

## 5. 報告書に書くなら
- 「検出の失敗を除いた、動作の成功率は、改善前後とも 91〜96%(区間は重なる)」と、「検出失敗は、照明の条件で大きく変わる(夕方の 5/28 → 深夜の 0/44)」を、分けて書く。後者は、**環境(照明)の管理が成功率の要件になる**という導入上の知見として使える。
- 「改善後に成功率が上がった」とだけ書くのは、上の 2、3 の混ざりがあるので、避ける。
