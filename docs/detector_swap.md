# 検出器を差し替えられる形に保つ

`src/hand_sim/vision.py` の「検出器の約束」と、`visual_servo.py` の `detector` 引数の考え方。答え合わせは `scripts/check_detectors.py`。

## 何の問題を解くか
今の検出は、「赤い画素を探す」という簡単な方法。sim の理想的な画像では十分だが、実機では、照明で色が変わる、
似た色の物が映る、など、すぐに崩れる。そのときに、**制御側のコードを書き直さずに**、検出だけを
既製の物体検出モデル(YOLO など)に取り替えられるようにしておきたい。

## 検出器の約束
```
detector(img) -> (u, v) または None
  img    : 高さ × 幅 × 3 (RGB, uint8) の画像
  (u, v) : 物体の中心の画素位置。見つからなければ None
```
この形を守る関数なら、何でも検出器として使える。制御側は、この形だけを知っている。

```
カメラ画像 ─→ [detector: 差し替える部分] ─→ (u, v) ─→ pixel_to_world ─→ (x, y) ─→ IK ─→ ctrl
                                                       └──── ここから先は、検出器が何でも変わらない ────┘
```

| 場所 | 変更 |
|---|---|
| `locate_cube` | 引数 `detector`(既定 `find_red_centroid`) |
| `locate_marker` | 引数 `detector`(既定 `find_blue_centroid`) |
| `collect_calibration_samples` | 引数 `detector`(既定 `find_blue_centroid`) |
| `servo_closed_loop` | 引数 `cube_detector`、`marker_detector` |

既定値が今までと同じなので、渡さなければ、今までどおりに動く(既存のチェックは全部そのまま通る)。

## 用意した検出器

| 検出器 | 中身 | 特徴 |
|---|---|---|
| `find_red_centroid` / `find_blue_centroid` | 赤(青)い画素すべての範囲の中心 | 簡単。遠くに小さな赤い点が1つあるだけで、中心が大きくずれる |
| `find_red_blob_centroid` / `find_blue_blob_centroid` | 一番大きな「つながった塊」だけの中心 | ごみ(小さな赤い点)に強い。`scipy.ndimage.label` を使う |
| `bbox_to_center` | 枠 (x0, y0, x1, y1) → 中心 (u, v) | 物体検出モデルを包むための部品 |

### 物体検出モデルへの差し替え方
YOLO などのモデルは、「画像 → 枠(と、種類・自信)」を返すことが多い。次のように包めば、検出器の約束を満たす。

```python
def yolo_detector(img):
    box = run_my_yolo(img)           # モデルを呼んで、一番自信のある枠 (x0, y0, x1, y1) を返す関数(自分で用意する)
    return bbox_to_center(box)       # 枠 → 中心 (u, v)。見つからなければ box=None → None

locate_cube(model, data, renderer, detector=yolo_detector)
```

## 試した結果(`check_detectors.py`)
3種類の検出器を、制御側のコードを変えずに差し替えて試した。

| 検出器 | 普通の画像(視覚の誤差) | 画像の隅に赤いごみを足したとき |
|---|---|---|
| A. 色検出(bbox) | 0.4〜1.3 mm | **132〜235 mm** 外れる |
| B. 色検出(最大の塊) | 0.4〜1.3 mm | 0.4〜1.3 mm(耐える) |
| C. 「物体検出モデル」のまね(枠 → 中心) | 0.4〜1.3 mm | 0.4〜1.3 mm(耐える) |

- 3つとも、普通の画像では同じ精度。**差し替えても、制御側は何も変えずに動く。**
- 赤いごみ(4×4 画素)が1つ映るだけで、A は 20 cm 前後も外れる。差し替える意味は、ここにある。
- 全体(closed-loop、カメラ位置を 2 cm ずらしたまま)を、B の検出器で動かしても、水平ずれは 0.5〜1.4 mm で届く。

### C について(正直な注意)
C は、本物の YOLO ではなく、「枠を返す関数」を色検出で代用したもの。B と同じく最大の塊を使っているので、
「ごみに耐えた」ことは、モデルの強さの証拠ではない。確かめたのは、**「枠を返す関数 → `bbox_to_center` → 検出器」という接続の形が、
そのまま動く**こと。本物のモデルの精度は、実機の画像で試すまで分からない。

## 限界(まだ解決していない点)
- **本物のモデルは使っていない。** YOLO などを入れるには、モデルの重みの用意、学習(または既製の重みの選定)が要る。実機の画像が手に入ってから試す。
- **1つの物体しか返さない。** 複数の物体の中から「どれを掴むか」を選ぶ処理は無い(必要になったら、検出器の戻り値を、リストに広げる)。
- **画素の中心しか返さない。** 物体の向き(回転)や、奥行き(高さ)は、検出器からは出ない。高さは、今は `CUBE_TOP_Z` を決め打ちしている。
- **照明・影への強さは未確認。** sim の画像は、照明が一定で、影も単純。実機で変わる。
