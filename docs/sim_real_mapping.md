# sim ↔ 実機の変換 ― 何を合わせるか

sim(MuJoCo)と実機(LeRobot)は、同じ関節名でも**単位・0 の位置・+ の向き**が違いうる。
この3つを関節ごとに合わせれば、sim で作った目標角度(`ctrl` [rad])を実機に送れる。

    実機の角度 [度] = 符号 × sim の角度 [rad] × 180/π + オフセット [度]
    (符号 = +1 か −1。オフセットは 0 の位置のずれ)

## 1. 単位
- sim: rad(ラジアン)。`data.qpos` と `data.ctrl` の単位。
- 実機: 度。ただし gripper だけは 0〜100 の別の尺度(下の 4. 参照)。

## 2. 0 の位置
- sim(`so101_new_calib.xml`): README のとおり、各関節の 0 が可動域の中央という想定。
- 実機: キャリブレーションで範囲の中央が 0 度になる(`docs/real_move_joints.md` の 1.)。
- つまり**どちらも「範囲の中央 = 0」なので、オフセットは 0 のはず**。ただし中央が物理的に同じ姿勢かは、実機で確認が要る。

## 3. 可動域の比較(sim の `range` はモデルから、実機はキャリブレーション結果)
| 関節 | sim の範囲(度) | 実機の範囲(度) | メモ |
|---|---|---|---|
| shoulder_pan | ±110.0 | ±119.1 | 実機の方が広い |
| shoulder_lift | ±100.0 | ±106.1 | 実機の方が広い |
| elbow_flex | ±96.8 | ±97.3 | ほぼ同じ |
| wrist_flex | ±95.0 | ±111.9 | 実機の方が広い |
| wrist_roll | −157.2〜+162.8 | ±180.0 | sim は非対称 |
| gripper | −10〜+100 | 0〜100(別尺度) | 変換が必要 |

sim の範囲は端から端まで中央対称ではない関節(`wrist_roll`)がある。
sim の目標を実機に送るときは、**狭い方(sim)の範囲に収める**と安全。

## 4. gripper
- sim: 回転関節 [rad]、範囲は −0.17〜1.75 rad(−10°〜100°)。
- 実機: 0(閉)〜100(開)の量(向きは実機で要確認)。
- 範囲同士を直線で対応させる(線形補間)のが最初の案。向きは実機の結果で決める。

## 5. + の向き(符号)
全関節とも MJCF では `axis="0 0 1"`(各関節の局所の z 軸)。世界座標での軸と、`q=+0.3 rad` にしたときの手先の動きを、
モデルから計算した結果(`q=0` では、上腕が立ち、前腕が前に水平に出ている形):

| 関節 | 世界座標での軸 | + にしたときの動き(sim) |
|---|---|---|
| shoulder_pan | 下向き (0,0,−1) | 真上から見て**時計回り**(手先は右 −y へ) |
| shoulder_lift | +y | 腕全体が**前・下**に倒れる |
| elbow_flex | +y | 前腕が**下**に曲がる(手先は下・やや手前) |
| wrist_flex | +y | 手先が**下**を向く |
| wrist_roll | −x | 土台側から手先を見て**反時計回り** |
| gripper | ほぼ −y | 開閉のどちらかは未確認(モデルの見た目で要確認) |

sim の動きは、ビューアで目で確認できる(右の Control パネルのスライダが各関節の `ctrl` [rad]):

    .venv/bin/python -m mujoco.viewer --mjcf=models/so101/scene.xml

実機側は、`real_move_joints.py` で + にしたとき上の表と同じ向きか逆かを、下の表に書く。
