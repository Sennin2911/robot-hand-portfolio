# 視覚サーボを1周つなぐ: 全体の流れと限界

`src/hand_sim/visual_servo.py` の考え方をまとめる。答え合わせは `scripts/check_visual_servo.py`。
新しい計算はなく、すでにある「目」(`vision.py`)と「関節角の計算」(`so101_ik.py`)をつなぐだけ。

```
overhead カメラで撮影
   │  locate_cube
   ├─ find_red_centroid ─→ 画像上の位置 (u, v) [画素]
   ├─ pixel_to_world    ─→ 床の位置 (x, y) [m]
   │
   │  plan_hover
   ├─ (x, y) に、自分で決めた高さ z を足す ─→ 目標 (x, y, z)
   ├─ solve_ik          ─→ 関節角 q (5個) [rad]
   │
   │  move_arm
   └─ ctrl に q を入れて mj_step を回す ─→ 腕が動き、手先が目標に届く
```

## 各関数の役割

| 関数 | 入力 → 出力 | 一言 |
|---|---|---|
| `locate_cube` | model, data, renderer → (x, y) または None | 撮影して、赤い立方体の床の位置を返す。見つからなければ None |
| `plan_hover` | (x, y), 高さ, 初期姿勢 → (q, ok) | 立方体の真上に手先を持っていく関節角を求める |
| `move_arm` | q → (腕が動く) | `ctrl` に目標角度を入れ、時間を進める |
| `gripper_position` | → (x, y, z) | 手先の今の位置。答え合わせ用 |

## なぜ z を自分で決めるのか
カメラは真上から見ているので、分かるのは床の (x, y) だけ。「どの高さに手先を持っていくか」は画像から出ない。
今回は立方体の上面(0.03 m)より上の 0.10 m にした。ぶつからずに、立方体の真上に止まるため。
掴むときは、ここから z を下げていく(未実装)。

## 奥行きの扱い(`CUBE_TOP_Z`)
`pixel_to_world` は「カメラから物体までの距離(奥行き)」で、画素を実寸に直す。
カメラが見ているのは立方体の**上面**なので、中心(0.015)ではなく上面の高さ 0.03 を渡している。
ここを間違えると、画面の端ほど位置がずれる。

## `plan_hover` が計算専用の data を作る理由
`solve_ik` は、計算のために `data.qpos` を何度も書き換える。動かしている本体の `data` を渡すと、
腕が勝手に別の姿勢にされてしまう。だから `mujoco.MjData(model)` で作業用のコピーを作り、そちらで計算する。

## 結果の読み方(`check_visual_servo.py`)

```
OK  立方体=(+0.220, -0.120)  手先=(+0.219, -0.119, 0.100)  水平ずれ(合計)=1.4 mm  内訳: 視覚=1.26 IK=0.09 動き=0.16 mm
```
- 「立方体」= 本当の位置(MuJoCo が知っている値)。「手先」= 腕を動かした後の位置。
- 「水平ずれ(合計)」= 手先と立方体の (x, y) の距離。これが 1cm 未満なら OK。3つの段階の誤差が全部入った値。
- 「内訳」は、合計を段階ごとに分けたもの。各段階が受け取った位置と、出した位置の距離を測っている。

| 内訳 | 測っているもの | 5か所の結果 | 誤差の原因 |
|---|---|---|---|
| 視覚 | 本当の位置 と カメラ推定 | 0.4〜1.3 mm | 画素は整数単位の粗さ。重心の取り方(赤い範囲の中心)の近似 |
| IK | IK への目標 と q から計算した手先位置 | 0.03〜0.10 mm | 反復を止める基準 `tol`(0.1 mm)の範囲内 |
| 動き | q から計算した手先位置 と 動かした後の手先 | 0.10〜0.20 mm | PD 制御の残り(重力で少し沈む等) |

- 合計の大半は**視覚**の誤差。IK と動きは、その 1/5 以下。
- 3つを足しても合計と一致するとは限らない(向きが逆なら打ち消し合う)。「どの段階が大きいか」を見つける目安として使う。
- sim では、カメラの位置が正確に分かっていて、画像にノイズもない。実機ではこの表の視覚と動きの行が大きくなる。

## open-loop と closed-loop

| | open-loop(今回) | closed-loop(次の段階) |
|---|---|---|
| 撮影 | 最初に1回だけ | 動かしながら何度も |
| 動き | 一度の計算で、目標まで一気に動く | 少し動く → 撮り直す → ずれを補正、を繰り返す |
| 誤差があると | そのまま残る | 見えている限り、ずれが縮まる |
| 向く場面 | sim(誤差がほぼ無い) | 実機(誤差がある) |

## 実機に移すと困る点
今回うまくいったのは、sim が完璧な前提でできているから。実機では次のずれが出て、open-loop では直せない。
- **カメラの位置・向きのずれ:** `pixel_to_world` は「位置と向きが分かっている」前提。実機では測って求める(ハンドアイ・キャリブレーション)。
- **サーボの誤差:** 指令した角度と実際の角度は、ぴったり一致しない(摩擦、たわみ、ガタ)。
- **アームが視界を遮る:** 近づくほど、アーム自身が立方体を隠す。今回は撮影時にたたんだ姿勢にして避けた。

これらは、`next_steps.md` の「次にやること」(closed-loop 化、キャリブレーションの考え方)につながる。

# closed-loop 化(第2週-5)

答え合わせは `scripts/check_closed_loop.py`。関数は `servo_closed_loop`(`visual_servo.py`)。

## なぜ「手先」も見る必要があるのか
最初は「動いたあとに立方体を撮り直す」だけで直ると考えたが、それでは直らない。
カメラの位置を間違って信じていると、立方体の推定位置は**毎回同じようにずれる**。撮り直しても、同じずれた値が出るだけ。
ずれを見つけるには、**手先も同じカメラで見て、立方体との差を取る**必要がある。

```
立方体の推定位置  c  = 本当の位置 + カメラのずれ
手先の推定位置    m  = 本当の位置 + 同じカメラのずれ
差 e = c - m        = 本当の位置どうしの差    ← カメラのずれが引き算で打ち消される
```
e を 0 に近づければ、カメラの位置が正確でなくても、手先は本当に立方体の上に来る。

## 1回のループ(`servo_closed_loop`)
1. 手先の青い目印を撮影して位置 m を測る。立方体の位置 c は、最初に測った値を使う。
2. 差 e = c - m。2 mm 未満なら終了。
3. 目標を `gain * e` だけ動かし、IK を解き直し、0.5 秒だけ動かす。1 に近い `gain` は測定誤差まで拾って揺れるので、0.8 にしている。

## 手先の「目印」を足した理由と、手先とのずれの扱い
- 手先(`gripperframe`)の位置に青い球を付けると、真上のカメラからはグリッパ本体の陰になり、ほとんど見えなかった(測定が 4〜7 mm ずれた)。
- そこで、上から見える位置(`gripper` リンクの +x 側)に目印を付けた(`MARKER_POS`)。
- 目印は手先からずれた位置にあるので、そのずれを、関節角からの順運動学(`forward_sites`)で計算して足し戻す。
  この計算はカメラを使わないので、カメラのずれの影響を受けない。
- 目印は XML ではなく `mujoco.MjSpec` で、読み込んだあとにプログラムで足している(原本の XML を書き換えないため)。

## 試した結果(`check_closed_loop.py`)
「プログラムが信じているカメラの位置」を、本当の位置からわざとずらす(実機で較正をミスした状況の再現)。

| 信じているカメラ | open-loop のずれ | closed-loop のずれ |
|---|---|---|
| ずれなし | 0.4〜1.4 mm | 0.4〜1.4 mm(同じ) |
| 横に 2 cm | 約 24 mm | 0.5〜1.4 mm |
| 高さ +3 cm | 4.8〜6.5 mm | 1.0〜1.9 mm |

- カメラが正確なら、open-loop と同じ(1 回で目標の 2 mm 以内に入るので、補正が働かない)。
- カメラがずれると、open-loop はずれがそのまま残るが、closed-loop は 2〜3 回の撮り直しで 2 mm 前後に収まる。

## 途中で起きた問題(次に生きる学び)
| 問題 | 原因 | 対処 |
|---|---|---|
| 手先の目印が見えず、補正が逆に悪化 | 手先に付けた球が、グリッパ本体の陰に隠れた | 上から見える位置に目印を移し、手先との位置の差を計算で補う |
| 立方体を弾いてしまった | たたんだ姿勢から短時間で動かすと、腕が勢いで下へ振れた | 最初の1回だけ 3 秒かけてゆっくり動かす |
| 目標が往復して収束しない | 腕が近づくと立方体が陰で部分的に隠れ、毎回の位置測定が 5 mm ほど揺れた | 立方体は、腕が視界に入る前に1回だけ測る |
| カメラが 2 cm ずれると、近い立方体を弾く | 手先が目標からずれ、立方体の 2.5 cm 隣に降りてグリッパが当たる | 弾かれた後は補正できない。テスト位置から外した(open-loop でも起きる) |

## 限界(まだ解決していない点)
- 立方体を最初の1回しか測らないので、**動く物体は追えない**。
- 目印を青い球にしているのは、sim だから。実機では、手先に目印の色を貼るか、ロボットの形そのものを検出する必要がある。
- 測定は 1 画素単位の粗さがあり、2 mm より細かい収束は狙っていない。
