# ロボットアームの「ぎこちなさ」と降下の振動: 原因の探し方と直し方(2026-10-29)

## 0. 結論(先に)
実機の動きには、別々の原因が 2 つあった。どちらも直した。

| 症状 | 原因 | 直し方 | 場所 |
|---|---|---|---|
| 動くたびに「止まる → 待つ → 小さく動く」。ぎこちない | サーボは毎回ほぼ同じ量だけずれて止まる(定常偏差)。それを、動いたあとに読んで直していた | 段階ごとの補正量を覚えて、次回は**最初から指令に足す**。止まったら待たずに次へ | `real_pick_place.py`(`servo_bias.json`) |
| 降ろすときだけ、激しく振動する | 降下が**遅すぎた**(約 4 秒)ことと、サーボの **P・D が合っていなかった**こと | P = 24、D = 64。降下は **0.5 秒** | `--arm-p` `--arm-d` `--descent-seconds` |

持ち上げは、最小 1.5 秒にしただけで済んだ(0.8 秒だと、サーボが指令に 4° 遅れ、止まる瞬間に行き過ぎる)。

## 1. 原因の探し方(順番)
1. **ログを見る。** 補正の表示(`補正1: ...`)が、毎段階に出ていた。量は毎回ほぼ同じ(elbow が −2° など)。→ 偶然のずれではなく、サーボの癖。
2. **「どの動きが悪いか」を、本人の目で切り分けた。** 持ち上げは問題なし、降ろすときだけ振動した。
3. **数値で比べる診断を作った**(`scripts/diagnose_vertical_motion.py`)。立方体なしで、降下と持ち上げを、条件を変えて往復し、50 Hz で「指令」と「関節の読み」を記録する。
   指標は 4 つ: 読みが止まった割合 `stall%`、指令との遅れの最大 `err_max°`、加速度の荒さ `jerk`、止まったあとの行き過ぎ `over°`。
4. **条件を 1 つずつ変えて、数値と目で見る。** 「仮説 → 実験 → 結果」を繰り返した(下の表)。

## 2. 実験の結果(何が効いて、何が効かなかったか)

| 変えたもの | 試した値 | 結果 | 判定 |
|---|---|---|---|
| 持ち上げの秒数 | 0.8 / 1.5 / 2.5 | 0.8 秒だけ、遅れ 4.0°、行き過ぎ 0.35°。1.5 秒以上は行き過ぎ 0 | 1.5 秒以上にする |
| サーボの加速度 | 254 / 80 / 40 / 20 | **何も変わらなかった**(stall 24〜32%、jerk 横ばい) | 仮説は外れ |
| P(追従の強さ) | 10 | **最も振動**(遅れ 3.6〜4.1°) | 下げると悪化 |
| D(揺れを抑える成分) | 32 → 64 | 少し減る。残る | 効く |
| P と D | **24 + 64** | **目で最も振動が少ない**(遅れ 1.58°) | 採用 |
| P と D | 32 + 64 | 24 より悪い(jerk 0.163) | 上げすぎ |
| 降下の秒数(P24 D64) | 4.0 / 2.5 / 1.5 / 1.0 | 速いほど安定。1.0 秒が最良 | 速くする |
| 降下の秒数(続き) | 0.7 / 0.5 / **0.3** | 0.5 秒が目で最良(行き過ぎ 0.53° = 手先で 2〜3 mm)。0.3 秒は行き過ぎ 1.49°(手先で 6〜8 mm)で、机の上 10 mm に近すぎる | **0.5 秒** |

## 3. 「なぜ降ろすときだけ」か(推測。直接は測っていない)
- 持ち上げは、モーターが重力に逆らう**一方向の負荷**を受け続ける。降ろすときは、重力が腕を押す側に変わり、**負荷の向きが入れ替わる**。歯車の遊びがあると、そこで揺れやすい。
- 遅い動き(降下 約 4 秒)ほど、「止まっては動く」(スティックスリップ)振動が出やすい。速く通り抜けるほど安定した。
- P を下げると遊びの中でふらつきが増え(悪化)、D を上げると揺れが減った。この向きは、上の説明と矛盾しない。
- **実機の降下が診断より悪かった理由**: 本番は、安全のため降下を 1.5 倍までに抑えていて、約 4 秒かかっていた。診断は 2.5 秒だった。

## 4. 測り方の限界(教訓)
- **数値が、見えている振動を拾えなかった。** `stall%` や `jerk` は、速さや加速度を変えてもほぼ同じで、目で見た差と合わなかった。50 Hz で読むので、10〜30 Hz の細かい揺れは見えない。
  → 数値は「持ち上げの行き過ぎ」「遅れ」「机への近づきすぎ」の**安全の確認**には使えた。振動そのものは、**目で比べた**。
- 最初の仮説(サーボの加速度が最大の 254 だから)は、**実験で外れた。** 外れたと分かるまで、1 つずつ試したのがよかった。
- 診断は、立方体を置かない(失敗しても壊れにくい)状態で行った。

## 5. 今の設定と、元に戻す方法
- 腕の 5 関節: P = 24、D = 64(LeRobot の既定は P 16、D 32)。**グリッパーは変えていない**(P は挟む力に比例し、クッションの調整が変わるため)。`--arm-p 16 --arm-d 32` で既定に戻る。
- 降下: `--descent-seconds 0.5`(慎重にしたいときは 1.0〜3.0)。`0` 以下で、従来の「計画の秒数 ÷ 1.5 倍」。
- 持ち上げ・上がる(段階 4、8): 最小 1.5 秒。
- 補正の先回し: 既定で有効(`--no-feedforward` で無効)。**P を変えたら、`calibration/servo_bias.json` を消す**(古い P のときの補正量が合わなくなる)。

## 6. 同じ調べ方を繰り返すとき
```

```
